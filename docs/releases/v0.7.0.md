# Elliot MCP v0.7.0 — a check that can actually block a merge

Until now the Elliot Action always reported a successful step, even when it had verified nothing. This release makes it usable as a required pre-merge check.

## New capabilities

- **Strict mode (opt-in).** `mode: strict` fails the job unless the verdict is `pass`. A report with findings, an audit that was skipped, a PR description too short to contain checkable claims, and a report whose claims are `UNVERIFIABLE` all fail the check instead of passing it. `mode: report` keeps the previous non-blocking behaviour and remains the default.
- **Deterministic verdicts.** The Action now computes one of four outcomes — `pass`, `findings`, `inconclusive`, `skipped` — from the report, and exposes it as the `verdict` output.
- **Codex integration.** A discoverable `elliot-verify-before-done` skill, and an opt-in Stop hook (`codex/stop-hook.mjs`) that calls the real Elliot MCP server to check an agent's claim that it changed files before the turn ends. The hook verifies uncommitted working-tree changes only; it does not verify tests, commits or deployments.
- **AGENTS.md.** An integration contract for coding agents: how to install Elliot with the user's consent, when to call each verification tool, and the rule that an inconclusive result is never reported as success.
- **Corrected plugin installation.** The Claude Code plugin needs two commands (`/plugin marketplace add`, then `/plugin install`); the README said one.

## Verification

Run `npm ci`, `npm run check` and `npm test` on Node 20 or newer. 45 tests pass, including six that exercise the strict-mode policy through the real CLI.

Install from GitHub: `npx -y github:EmanueleCell4/elliot-mcp#v0.7.0 init`

## Enabling the gate

```yaml
- uses: EmanueleCell4/elliot-mcp@v0.7.0
  with:
    mode: strict
    anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
```

A ready workflow is in [`examples/workflows/`](../../examples/workflows/). To block merges, add that job as a required status check in your branch protection rules.

## Limitations

- A passing check means the claims in the pull request description are supported by evidence in the code. It is not a security audit and does not establish that the change is correct.
- Enforcement on pull requests from forks has not been validated. Do not enable it there without reviewing credential exposure and runner isolation first.
- The Codex Stop hook is a limited gate: it can be bypassed by the operator and is not a security control.
- This release is not certified production-ready.

## Distribution

This GitHub source release does not publish `elliot-mcp@0.7.0` to npm. Use the GitHub source installation command above until npm publication is separately confirmed.
